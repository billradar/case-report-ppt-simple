# 安全工作流

## 0. 环境准备

- **检查是否已安装 ppt-mcp（PowerPoint MCP）**：https://github.com/ykuwai/ppt-mcp （`uvx ppt-mcp`，需 [uv](https://docs.astral.sh/uv/getting-started/installation/) 与本机 Microsoft PowerPoint）。
- 探测：调用 `ppt_get_app_info` / `ppt_list_presentations`。**有返回 → 已安装，跳过安装，直接进入 §1**。
- **未安装 → 安装，然后请用户重启后继续**：
  1. 确认 `uv` 可用（`uv --version`），缺失则先安装 uv；
  2. 写入 MCP 客户端配置：OpenCode（`opencode.json`）用 `{"$schema":"https://opencode.ai/config.json","mcp":{"powerpoint":{"type":"local","command":["uvx","ppt-mcp"],"enabled":true}}}`；其他客户端用 `{"mcpServers":{"powerpoint":{"command":"uvx","args":["ppt-mcp"]}}}`；
  3. **提示用户重启 OpenCode / 会话**（MCP 仅启动时加载），重启后继续执行；
  4. 仍不可用 → 无 MCP 时可退回 PowerShell COM / python-pptx，确实无自动化能力时降级为“只整理内容与可执行修改清单”，不伪称已改 PPT。

## 1. 接收与边界确认

- 确认源文件、最终文件名、病例资料来源、允许调整范围和交付路径。
- 模板选择：用户指定了已有 PPT（如某科室病例汇报）时，以该已有 PPT 为模板进行改造；未指定、或用户要求「根据模板生成」时，先确认模板文件存在，再用文件系统把 skill 内通用模板 `templates/病例汇报_通用模板.pptx`（见 SKILL.md 约定常量）复制到目标 PPT 目录后作为起点，不直接编辑母版。模板缺失时优先采用用户提供的 PPT 副本；若都没有，请用户提供可编辑模板，不凭空声称模板保真。
- 记录用户明确允许变更的页面/元素；未授权项默认保护。
- 病例资料来源：优先采用操作者自行提供的详细病例（病史、查体、检验、影像、诊断、治疗等），以其为唯一事实来源；未提供真实病例或明确要求教学改编时，可据科室与病种生成去标识化教学病例及必要的相关体征与合理检查结果；在交付说明中注明生成项和待临床核实，不把生成值混入真实病例。
- 若病史或检验资料不完整，列出缺口，不以“合理推断”补成患者事实。

## 1.1 PowerPoint 可视编辑与回读

先确认用户能看到当前 PowerPoint 桌面窗口。在该窗口打开工作副本并核对活动演示文稿路径；通过实际可用的 `ppt_*` 工具逐页编辑，适时切换当前页，使写字、局部着色和扩页的过程能在窗口中看到。每小批操作后回读对象或预览核验，保持窗口打开直至保存完成。不要把工具调用文本当作可视编辑。若 PowerPoint/MCP 运行于用户看不到的环境，不得声称“可见操作”；说明限制，询问是否接受文件级替代流程。

## 2. 保护原件：先复制，后打开编辑副本

OneDrive/PowerPoint 的 AutoSave 可能实时写回当前文档。安全顺序必须是：

```text
源 PPT（只读基线）
  → 打开/检查
  → 立即 Save As 到同级或指定的临时副本
  → 验证标题栏、当前激活演示文稿和完整路径
  → 只编辑该副本
```

使用 skill 内母版模板（`templates/病例汇报_通用模板.pptx`，见 SKILL.md 约定常量）时：先用文件系统 `Copy-Item` 把母版复制到目标 PPT 目录并命名，再打开该副本编辑；母版本身永不打开、永不修改。

建议名称：`病例汇报_YYYYMMDD_working.pptx`；最终版为 `病例汇报_YYYYMMDD_final.pptx`。不要把工作副本命名为笼统的 `test.pptx`，以免误覆盖或难以追溯。

若源文件已被 AutoSave 改动：立刻停止继续修改；保留当前状态；优先从版本历史、只读副本或云端版本恢复，再重新建立工作副本。不要用未经确认的版本覆盖原件。

## 3. 基线盘点

在改字前记录：

- 幻灯片数、顺序、节标题、页面比例、主题和母版线索；
- 每页背景、Logo、页码、页眉页脚、固定装饰和不可编辑对象；
- 文本框、表格、图片、图表、组合对象、备注、动画和切换；
- 溢出文本、低清图片、空白占位符和已存在的格式异常。

必要时截取编辑前预览，便于对照。只在目标副本中修改。

## 4. 建立统一病例数据源

先用结构化草稿区分原始资料与教学生成项，并维护 PPT 外的 `NAME-科室-病例汇报_生成清单.md`（逐项记录最终采用的关键体征、检查、诊断；来源类型、原资料定位或生成依据、页码和待核实点），统一所有数值、日期、单位、诊断名称与时间线，再写入任何页面。字段和核验规则见 [medical-content.md](medical-content.md)。

将每个结论回链至病例来源：病史、查体、化验、影像、病理或会诊记录。无法回链的内容不放入定论性页面。

## 5. 择要撰写与标红

先判断每页用途，挑选与该病例诊断、鉴别、处置和转归相关的事实，在现有对象内自行组织语言；不逐项搬运所有体征，不机械对应占位词。评分只在提供了可靠评分及依据、且对该病例有解释价值时使用，不强制套用 NIHSS 或其他疾病量表。逐页写入，不改变原页面顺序、文本框或表格结构、位置、尺寸、字体、字号、段落格式、动画和切换。内容超过原有空间时先精简措辞；仍无法容纳时复制现有同类页面，紧接对应页面插入，把后续事实原位写入复制页。保留其布局、字体、对象、表格结构、动画与切换；无同类页面可复制时列在交付说明中，不缩字或扩框。

依据 [medical-content.md](medical-content.md) 仅对关键阳性事实、异常数值及最终诊断关键短语的字符范围标 `#EE0000`。保留单位、参考范围、时点；对无法可靠定位或会清除字体格式的写入操作，跳过该对象并记录。

## 6. 渐进保存与失败恢复

- 在完成一个章节或一批页面后保存工作副本；重大重排前额外生成带时间戳的恢复点。
- 一次只做可验证的变更；失败时撤销当前小批次或回到最近恢复点，而不是在损坏文件上叠加修补。
- 若某对象的编辑会破坏格式或无法可靠定位，保留原对象并记录未写入内容；不得另建替代元素破坏固定布局。
- 若 PowerPoint、MCP 或 COM 失去连接，先保存可保存的工作副本、关闭异常会话、重新打开副本并核对页数与最后成功修改；不得假定未保存操作已生效。

## 7. 最终化

完成最终副本后，执行 [validation.md](validation.md) 的内容、视觉、技术和交付检查。确认最终文件可重新打开且所有页面完整后，交付时删除工作副本，只保留最终版和原件（目标目录不留工作副本）；如确需回溯，可在删除前把一份带时间戳的恢复点存到目标目录之外。
